### Sequencing and PR policy

1. **Safety and diagnosis:** DCK-001–004. An imported appearance must not license destructive saving.
2. **Reusable authoring:** DCK-005–011, with DCK-014 asset ownership integrated before cross-document templates. Rich text and composition precede feature breadth.
3. **Business content and output:** DCK-012–020. Preserve/warn for unimplemented content throughout. DCK-015 playback is a separately admitted expansion, not a prerequisite for an honestly scoped static-talk release.
4. **Graduation:** DCK-021 consumes evidence from every admitted package and shared gates.

Each package is an outcome, not permission for a giant PR. Its PR-boundary paragraph defines reviewable vertical increments. Commit, open a scoped PR, collect relevant CI against that revision, merge, then start dependent cutovers. Independent CI jobs may run in parallel; do not combine half-migrated shared models. Model changes must update both format adapters, snapshots, undo, collaboration serialization and all exhaustive matches in the same mergeable increment. No permanent compatibility aliases or a second slide engine. No broad dependency/UI rewrite.

## 2. Common implementation and verification contract

**Canonical ownership.** Extend `decks-core/src/controller.rs`, `ops.rs` and the shared `History<Op>`. GTK owns widgets, focus surfaces and temporary input previews, not a second document. A completed gesture, paste, merge, theme application or layout reassignment is one transaction. Invalid/no-op/cancel changes do not dirty the document or clear redo. Undo restores identities, content, inheritance, asset references, build targets and selection; allocating a new object on redo must not change its identity. Selection-only movement is not a document edit.

**Model migrations.** New persistent state must be present in `engine::Deck`, `ops::DeckDoc`, `DecksController::deck`, import/export, `snapshot.rs`, recovery and `collab.rs`/`collab_tests.rs` where those features serialize it. `snapshot.rs` is test introspection, **not** a recovery serialization format. Preserve old recovery envelopes through the shared migration policy; never pretend defaults recovered content absent from a legacy snapshot. Readers assign IDs to legacy input once. Persist source-to-model IDs in package context, not positional guesses after reordering. Avoid changing the shared Letters `Run` ABI merely to add Decks inheritance; use the Decks-owned binding projection described in DCK-006.

**Format proof.** For every admitted feature, exercise independently authored PPTX and independently authored ODP; import → unrelated edit → same-format save → reopen; supported feature edit → save → reopen; both cross-format directions; our output → LibreOffice rewrite → our reader. Compare editable semantics and rendered slides, including non-title slides. Check package relationships/content types/ODF manifest and referenced assets, not only ZIP validity/text extraction. Missing required LibreOffice is a failed required lane (`REQUIRE_SOFFICE=1`), not a pass. Office comparisons require licensed access or revision-matched publisher evidence; disagreements are recorded, not silently declared resolved.

**CI profiles used below (requirements, not commands executed here):**

- **C:** existing `.github/workflows/ci.yml` core/workspace tests, Python contract validators, capability/lane inventory and compilation of all feature combinations affected by the model. Extend `decks-core/tests/controller_property.rs`, `ops_property.rs`, `stateful.rs`, `malformed_inputs.rs` when adding operations or parsers. Shared dependency changes retain all-app checks.
- **G:** `.github/workflows/gui-tests.yml` using `tests/gui/run_gui_tests.sh`; proposed journeys go in `tests/gui/test_smoke.py` unless stated otherwise. Use actual keys/pointer/AT-SPI controls, bounded predicates, normalized snapshots and saved/reopened files. Test-only actions can inspect state or inject failures, not substitute for the user action under test. Retain action coverage through `tests/test_decks_action_inventory.py` and `docs/DECKS-ACTIONS.md`.
- **R:** `.github/workflows/render-parity.yml`, `render-real.yml`, `tools/render-lab/fixtures.py`, `edit_journeys.py`, `tests/gui/test_edit_render.py`, and `decks-core/tests/soffice_oracle.rs`. Capture import, edited output and reopen separately; ratchets cannot be relaxed to hide defects. `decks/src/export.rs` tests require Poppler tools in their required lane.
- **V:** `.github/workflows/visual-matrix.yml` and existing `tests/gui/visual/expected/` matrix: widths 400/800/1280, light/dark/high contrast and scales 1/2. Add real fractional-scale GNOME evidence where specified; simulated scaling does not certify a compositor.

## DCK-001 — Complete the compatibility envelope and live loss planning

**Goal/problem and evidence.** `decks-core/src/loss.rs::content_a_save_drops` is a bounded lexical scan of the disk source for selected losses. `decks/src/loss_ui.rs::save_after_asking` blocks failed inspection and asks for admitted drops, but reports largely feature labels. `engine/chart.rs` explicitly reads only the first chart series; theme/group/table limitations extend beyond the scanner's current list. Publish a truthful per-format matrix before expanding editing.

**Targets/ownership/dependencies.** `decks-core/src/loss.rs`, `lib.rs::{FORMATS,read_deck_with_report,write_deck}`, `engine/{parse,write,chart,table,text_body}.rs`, `odp.rs`, `decks/src/{loss_ui,window}.rs`, `interop/corpus.json`, `docs/DECKS-ACTIONS.md`. Use shared `CompatibilityReport`/`FeatureDisposition` and the parent-owned save-planner contract; do not introduce another compatibility vocabulary. No predecessor; DCK-002 consumes its dispositions.

**Ordered implementation.** (1) Inventory text/run/paragraph/font attributes, page size, backgrounds, master/layout/theme inheritance, placeholders, shape geometry/paint, groups, images/links/alt text, table spans/styles, chart series/data, notes, hidden slides, builds/transitions, media, comments/review, SmartArt/OLE and package extensions. For each direction record editable, safe opaque, explicit loss or blocked, with a fixture and source location. (2) Replace prefix-sensitive lexical guesses for modeled package analysis with namespace/relationship-aware bounded parsing; retain source-inspection hard errors. (3) Produce target-format reports with stable feature IDs, affected slide/object/part, reason, and available copy/cancel/repair action. A supported field that cannot be written is a hard error, not a generic Save Anyway. (4) Route Save, Save As, close guard, recovery save and output preflight through that plan; propagate partial/over-budget inspection as incomplete, never clean.

**Edge/loss/undo.** Namespace aliases, duplicate relationship IDs, external links, malformed optional parts and unsupported content inside an otherwise supported slide must be classified. Planning never edits/history-records. Consent is for a particular revision/target/loss report and expires if those change; cancelling retains dirty edits, source bytes and recovery state.

**Tests/GUI/render/CI.** Extend `loss.rs` unit tests, `decks-core/tests/{hostile_packages,malformed_inputs,package_consistency}.rs`, existing `DecksUnsupportedContentSmoke` and `DecksSourceInspectionSmoke`. Add proposed `loss_matrix_names_slide_and_target`, `namespace_aliases_do_not_bypass_loss_detection`, `incomplete_analysis_never_authorizes_save`, and `DecksLossDetailsSmoke`. Fixtures belong in existing `interop/packages/{pptx,odp}/` with new clearly versioned manifest entries. C+G+R; render unsupported constructs as declared previews without confusing previews with retained editability.

**Acceptance/non-goals/PR boundary.** Every inventory row has a deterministic disposition in both formats; all destructive live paths enforce it. No claim of general opaque preservation or new media/chart support. Land inventory plus detector/GUI rows in feature-family PRs, each maintaining complete safety for its admitted scope.

## DCK-002 — Session-owned package provenance and relationship-safe preservation

**Goal/problem and evidence.** Some preservation already exists: `lib.rs::read_deck_with_report` captures `OpaquePackage`; `window.rs::save_deck` uses `suite_common::carry::capture(...).write_with(...)` before committing a staged location. However `open_path` calls `read_deck`, not the reported loader; saving recaptures the disk source. The helper `write_deck_with_opaque` separately calls write then append. Do not describe this as no opaque support, or confuse it with a complete retained package graph.

**Targets/dependencies/model.** DCK-001 and shared atomic save/location contracts. Targets `decks-core/src/{lib,loss,controller}.rs`, both writers/readers, `decks/src/{window,loss_ui,persistence}.rs`. Reuse shared `OpaquePackage`/carry rather than forking it. Proposed `DeckSourceContext` is controller/session-owned: format, original identity/fingerprint, bounded captured package graph/bytes, source part↔stable model-ID map, import report and mutation dependency set. It is not widget state and cannot be reconstructed from the current filename alone.

**Ordered implementation.** (1) Capture model, report and source context from the same opened bytes and install them together only after successful import. (2) Define graph ownership: unrelated opaque subgraphs survive only when all internal targets/content types/manifests remain valid; modifications to a referenced slide/object/layout/theme invalidate only explicitly known dependent opaque content. Unknown dependency means block preservation or ask for a lossy copy, never guess. (3) Serialize modeled changes and retained parts into one staged package, remapping IDs and relationships collision-free; validate before atomic commit. Remove/bypass no safety boundary with the write-then-append helper; migrate its callers to the single transaction API. (4) On same-format Save As retain safe context; cross-format conversion reports incompatible opaque content. (5) Before overwrite compare current source identity to the captured one and use the shared concurrent-writer exclusion mechanism. External change offers reload or distinct copy, not silent merge. Update session baseline only after the actual destination/upload commit succeeds.

**Edges/undo.** Deleted/reordered slides, copied groups, shared assets, dangling external relationships, unknown animation targets, layout/theme replacement and package paths containing `..` require deterministic policies. Never fetch external URLs or execute OLE/macros. Undo restores dependency state or recomputes it from the canonical revision; it cannot forget that unsupported content became unsafe. Unknown parts are bounded immutable bytes shared across revisions, not cloned per keystroke.

**Tests/CI.** Extend `decks-core/tests/{package_consistency,snapshot_fidelity}.rs`, `loss.rs`, and existing `DecksOpaquePartsSmoke`, `DecksUnsupportedContentSmoke`, `DecksSourceInspectionSmoke`. Proposed `opaque_dependency_survives_unrelated_edit`, `deleting_target_cannot_leave_dangling_relationship`, `external_replacement_requires_copy`, `DecksSourceContextSmoke`. Assert byte-identical preserved parts plus graph validity; inject source deletion/replacement after open and destination creation after dialog. C+G+R, shared atomic fault sweep, I staged remote save.

**Acceptance/non-goals/PR boundary.** Unrelated edits preserve every feature advertised opaque; dependent edits fail safely or obtain precise lossy-copy consent. No general semantic editing of comments/SmartArt/OLE. First PR carries context end-to-end and preserves current safe subset; subsequent PRs expand relationship families with fixtures. No mixed old/new live save paths after a cutover.

## DCK-003 — Recovery preserves the full editable document and reports serialization failure

**Evidence/goal.** `window.rs` autosave callbacks use `write_deck_bytes` inside `if let Ok(...)`; only subsequent slot-write errors reach `AutosaveNotifier`. The recovery payload is currently rebuilt PPTX/ODP model output, not retained source context. Existing multi-document, interrupted-save, double-crash and unattended-autosave journeys are substantive and must remain. Recovery must not silently shed new model fields, opaque content or owned assets.

**Targets/dependencies/model.** DCK-002 plus DCK-005 revision semantics; `decks/src/{window,persistence}.rs`, `DecksWindow::{recover_from_snapshot,open_path}`, `decks-core/src/lib.rs::write_deck_bytes`, `decks-core/tests/snapshot_fidelity.rs`. Shared owner implements envelope/migration/ownership primitives. Decks supplies one versioned payload containing canonical semantic state, assets and source context needed to make the next save safe. The shared envelope binds payload, original location, format, revision and checksum.

**Steps.** (1) Route serialization and slot-write failures through the existing notifier and preserve the prior valid generation. (2) Capture a consistent revision; if background serialization is added, never mark a later revision snapshotted. (3) Encode all Decks metadata not representable in interchange, with bounded decoding and explicit version handling; retain the existing package-shaped snapshots as a readable migration input. (4) Reinstall recovered document/context/assets as one session; retain the double-crash adoption ordering before orphan cleanup. (5) Preserve original non-UTF8 identities using the shared path type or reject unsupported identities visibly before storing a lossy string. Do not infer missing opaque content was safe from a legacy snapshot.

**Edges/undo.** Crash during master/layout/rich-text sessions, source moved/offline, two windows, concurrent snapshot worker, conversion Save As, corrupt one of many orphans, old schema and exhausted disk. Recovery restores committed document state; uncommitted IME/cancelled gestures are not fabricated edits. Recovered work is dirty even when its last persisted revision matches an old source. Undo history persistence is not required, but the initial recovered state must include all committed edits and identities.

**Tests/GUI/render/CI.** Extend `snapshot_fidelity.rs` and existing `DecksRecoveryIsItselfProtectedSmoke`, `DecksEveryCrashedDocumentSmoke`, `DecksKilledMidSaveSmoke`, `DecksUnattendedAutosaveSmoke`. Proposed `recovery_keeps_opaque_graph_and_assets`, `serialization_failure_retains_last_generation`, `DecksRichRecoverySmoke`. Kill/relaunch, save/reopen both formats, assert notes/styles/groups/theme overrides/assets and render after recovery. C+G+N+I; legacy snapshot fixture generated from the recorded previous payload version.

**Acceptance/non-goals/PR boundary.** A restored document cannot claim source-loss safety it no longer possesses; every autosave failure is visible without notification spam, and a valid previous generation remains recoverable. No new shared recovery service. Separate error-propagation PR, then versioned payload plus migration PR, then new-feature recovery regressions in each feature PR.

## DCK-006 — Explicit dimensions and theme/layout/master inheritance

**Evidence/goal.** `Deck` holds slides/masters only; `MasterSlide::page_emu` on the first master controls output. `parse.rs::read_pptx` reads `ppt/theme/theme1.xml`; `write.rs::theme_part_xml` emits conventional slots and one master's font. `layouts::effective_master` combines concrete backgrounds/decorations. Preserve editable inheritance rather than only resolved appearance.

**Targets/dependencies/model.** DCK-001/002/005. `engine/{model,parse,write,shape,text_body,placeholders,text_xml}.rs`, `layouts.rs`, `odp{,_layouts,_graphics,_text}.rs`, `format.rs`, `decks/src/{canvas,text_render,export,format_inspector}.rs`. Proposed `Deck.page_size`, `ThemeId`, stable `MasterId`/`LayoutId`, typed color/font tokens and color-map overrides. Keep normalized 960×540 coordinates for this cutover, but preserve authoritative source page dimensions once at document level; all format/export conversions use one tested conversion, not first-master fallback. Mixed-page ODP dimensions must be explicitly represented per page or classified as unsupported conversion, never silently use the first page.

**Steps/model detail.** (1) Separate inherited absence, explicit local value and token reference for background, fill/stroke, default text/paragraph style and placeholder geometry. Do not turn an absent value into white/Sans at import. (2) Retain each master/theme relationship and source token/modulation; resolve precedence object/run override → matching layout placeholder → master placeholder/default → theme → documented fallback. Match placeholders by stable source index/type, not the nth body alone. (3) Keep shared Letters `Run` as resolved rendering/clipboard value; introduce a Decks-owned style-binding layer keyed to stable text-span identities, with token/local/inherit values as canonical source and resolved `RunStyle` as derived cache. Rich-text split/merge operations update bindings atomically; never independently editable cached RGB and token. (4) Make one resolver consumed by canvas, thumbnails, presenter and export. (5) Writers emit inherited relationships/tokens where the target supports them; format conversions incapable of equivalent inheritance retain appearance and declare the editable-semantics loss. (6) Migrate all literals, history, recovery and collaboration serialization.

**Edges/undo.** Multiple themes with same names, cycles/missing parents, scheme overrides, tint/shade/alpha, unknown tokens, direct formatting on inherited text, custom size, mixed masters, duplicate body placeholders. ## DCK-017 — Real GNOME/Wayland monitor privacy and fallback

**Evidence/goal.** `presenter.rs::{show_layout_on,layout_after_monitor_change}` operates on monitor indices. `presenter_window.rs` fullscreen audience placement and disconnect banners exist, but normal presenter placement is compositor-controlled. **Steps.** (1) Enumerate user-readable displays and provide an identify/preview step showing audience-safe labels only. G+V+I. Test real distinct and mirrored displays; simulated success remains labeled simulation.

**Acceptance/non-goals/PR boundary/prerequisite.** Demonstrated private notes, correct audience output and safe fallback on named real hardware; unsupported compositor constraints have a safe user-facing mode. No remote display protocol.
